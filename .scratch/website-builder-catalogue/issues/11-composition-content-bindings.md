## Question

Which native block, recipe, layout-section and collection-binding behaviors should be supported without turning the generic builder into a hardcoded institutional application?

## Boundaries and expected evidence

Specify typed composition/nesting constraints, reusable-section references, dynamic listings/detail data, approved recipes and safe empty/deleted-reference behavior. Distinguish permission Page sections from visual Layout sections. Set reuse versus extension boundaries using registered starter functionality.

Coverage: CORE; PAGE; BLOCK; ACTION; CONTENT; GLOBAL; PREVIEW. Acceptance remains in the [implementation checklist](../../../docs/planning/feature-implementation-checklist.md).
